# Replay Chess: design coverage (every board → phase → feature, and the flow map)

Status: **final, revision 2**, 2026-11-02. This file is the board → phase → feature matrix of `SP/plan/allocation.md` §4, corrected by `SP/plan/critique-coverage.md` and by the final phase specs in `docs/plan/phase-NN-*.md`, plus the full edge list of the flow map `SP/design-ref/project/v2/V3FlowMap.dc.html` (decoded in `SP/plan/inv-sys.md` §1.2). `SP` = `/private/tmp/claude-501/-Users-rohitpandit-open-source-chess-battle-turbo/8433de47-73d2-466e-945c-3c2450748123/scratchpad`; boards are `SP/design-ref/project/<File>`; the index of all boards is `SP/design-ref/INDEX.md`.

**Authority.** The v3 pages (`v3pub`, `v3play`, `v3rct`, `v3acct`, `v3sys`) are authoritative; v1 and v2 boards are superseded explorations (ideas only). Every v3 board has exactly one owning phase; a phase that only shows another phase's slot "lights it up" (allocation §1.2). The 55 `V3Game` template states are specified row by row in P2 §4.3, which is the checklist for every board built on that template (`V3GameOverLegend` in P3, `V4TournamentGame*` in P12).

**How it was checked** (critique-coverage §1, scripts in `SP/critic/`, run with `python3 -I`): every board stem and every `data-props` enum value appears in its owning phase doc (314/314 boards, 2,983/2,983 values); a strict pass confirmed each value has a trigger and a rendering; every CTA and in-board link target was searched in the owning doc; every route referenced by a phase was matched to the phase that defines it; every flow-map edge was matched to the source screen's doc. CI keeps it true from P1: `docs/qa/design-states.json` (generated from the boards) and `scripts/qa/state-coverage.ts` fail a build with a missing state (`01-architecture.md` §5.12).
