# QA records and design-state coverage (`docs/qa`)

| File | What |
|---|---|
| `phase-NN-signoff.md` | The sign-off template (plan §12.9, CT X15). Copy it to `phase-<NN>-signoff.md` at the start of a phase's dev-site pass. |
| `phase-01-signoff.md`, `phase-01/` | Phase 1's record and its screenshots (ego-browser `page.screenshot`, JPEG). |
| `design-states.json` | Every state of every design board (`.dc.html` in the design reference), generated by `scripts/qa/extract-design-states.ts`: `{ board, phase, props: { prop: [values] } }`. |
| `design-states.overrides.json` | Reviewed exceptions: `ignore` (not a state), `demoOnly` (a `/dev/ui` demo is enough, with the reason), `deferred` (the state ships in a later phase). |
| `phase.txt` | The open phase. Boards of later phases are not counted. |

## Design-state coverage

Specs tag the states they reach in their titles: `@state:<Board>.<value>` on a real route with real data, `@demo:<Board>.<value>` on a demo route. A state with no tag is **missing**; one reached only by a demo with no `demoOnly` reason is **unexplained**. Either fails.

```sh
# Tags only (fast; a skipped or failing test still counts): CI's nightly check
pnpm exec tsx scripts/qa/state-coverage.ts --only-phase 1

# Reached (for the sign-off): the json reporter output of real runs, only passing tests count
pnpm exec tsx scripts/qa/state-coverage.ts --only-phase 1 --require-run \
  --from-json apps/web/test-results/results.json --from-json <devices results.json>
```

The script prints its mode first (`tagged` or `reached`). Paste the `reached` table into the sign-off record; the `tagged` table only proves the tags exist.

## Sign-off record, in order

1. Header: the tested `dev` SHA, the Vercel deployment id, the OCI socket image tag, the test window (at least 24 h after the last dev deploy).
2. CI evidence (`ci.yml`, `nightly.yml`, `post-deploy-dev.yml` run links) and the quarantine list.
3. Owner tests T1–T26 with pass/fail, screenshot paths and notes; the manual checks (SPEC §12.5 M1–M11, plan §12.7 B1–B12).
4. Devices: real model and OS, browser and version, zoom levels.
5. Design-state coverage (above) and the board-by-board parity table.
6. `pnpm exec tsx scripts/qa/error-window.ts --since <last dev deploy>`, every new issue triaged.
7. Telemetry (PostHog live view) and the k6 results (`perf/results/`, `perf/compare.ts`).
8. Defects, each with its `regression:` test (CT X14), and the Definition of Done ticked with evidence.
